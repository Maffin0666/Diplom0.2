# Установка и запуск серверной части

Сервер рассчитан на Python 3.12, процессор без CUDA и установленный FFmpeg. Веса EasyOCR и TrOCR загружаются один раз отдельной командой; при обычном запуске сервер использует только локальные файлы. Модель Silero расположена в `server/models/silero_v4_ru.pt`. Один процесс Uvicorn последовательно обрабатывает тяжёлые задания, чтобы несколько запросов не перегрузили память ноутбука.

## Установка на Windows

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m scripts.prepare_models
.\.venv\Scripts\python.exe run.py
```

Команда подготовки моделей требует интернет. Затем сервер можно запускать без интернета. FFmpeg должен быть доступен через `PATH` либо через полный путь `FFMPEG_BINARY` в `.env`; рядом с ним нужен `ffprobe`. На этом ноутбуке рабочий FFmpeg найден в составе GNU Octave, а его путь уже указан в локальном `.env`. Если модели или FFmpeg отсутствуют, `/health` ответит 503 и загрузка фотографии тоже вернёт 503. Ошибка указывается в журнале сервера.

Параметры по умолчанию находятся в `server/config.py`. Для изменения скопируйте `.env.example` в `.env` **в корне проекта**. Сервер читает этот файл независимо от текущей папки запуска. `HOST=0.0.0.0` разрешает подключение телефона через локальную сеть: используйте адрес ноутбука, например `http://192.168.1.10:8000`, и проверьте правило брандмауэра. Установите `HOST=127.0.0.1`, если нужен доступ только с ноутбука.

`requirements-tts-optional.txt` содержит необязательные pyttsx3 и gTTS. По умолчанию используется локальный Silero; автоматическое переключение выключено. Чтобы при отсутствии Silero использовать установленный русский системный голос pyttsx3, установите необязательные зависимости и задайте `USE_FALLBACK_TTS=true`. Сетевой gTTS доступен только при одновременных `TTS_ENGINE=gtts` и `ALLOW_ONLINE_TTS=true`.

## API

- `GET /health` — готовность OCR, TTS и FFmpeg; 200 при готовности, 503 при отказе.
- `GET /info` — фактически выбранные устройство, TTS-движок и состояние очереди.
- `POST /api/v1/recognition/upload` — поле `file` с JPEG, PNG или WEBP; успешный приём возвращает 202 и `task_id`. Необязательный заголовок `X-Upload-Id` с UUID предотвращает повторную обработку снимка при сетевом повторе. Очередь заполнена — HTTP 429 с `Retry-After`; тот же UUID с другим снимком — HTTP 409.
- `GET /api/v1/recognition/status/{task_id}` — `pending`, `processing`, `completed` или `failed`.
- `GET /api/v1/recognition/result/{task_id}` — манифест. Для завершённой обработки, включая состояние `failed`, возвращает 200. При `failed` распознанный текст, если доступен, остаётся в `full_text` и `chunks`; `audio_url` отсутствует. Пока задача выполняется, сервер возвращает 202.
- `GET /audio/{filename}` — готовое MP3 после успешного завершения. В манифесте `audio_url` содержит относительный адрес. `bbox` и `image_width`/`image_height` относятся к исходной фотографии.

Лимиты по умолчанию: 15 МиБ на файл, 20 млн пикселей и 6000 пикселей по каждой стороне. Одно задание обрабатывается, ещё два ожидают (`MAX_PENDING_TASKS=2`). Манифесты и статусы записываются в `server/data/tasks.sqlite3`; базу можно перенести настройкой `TASK_DB_PATH`. Завершённые задачи доступны по старому `task_id` после перезапуска. Прерванные задачи переходят в `failed`, поскольку загруженное фото не хранится на сервере. Для их повторной обработки клиент сохраняет фото локально и отправляет его с новым UUID. Серверные аудиозаписи сохраняются до ручной очистки администратором; автоматическое удаление не настроено.

Описание мобильного клиента и протокола находится в `client/README.md`. Машиночитаемая схема лежит в `client/api/openapi.v1.json`, обновляется командой `python -m scripts.export_openapi`. Для проверки полного маршрута на запущенном сервере используйте `python -m scripts.smoke_client_api --image test_lecture.jpg`.

## Проверка

Журнал сервера сохраняется в `server/logs/server.log` (UTF-8, время UTC). В нём есть `task_id`, стадии `accepted`, `preprocess`, `ocr`, `segment`, `audio`, `complete` или `failed`, длительность этапов и число найденных строк/формул. Содержимое фотографии и распознанные фразы в журнал не пишутся. Ежедневные архивы сохраняются без автоматического удаления. Папку можно изменить через `LOG_DIR` в `.env`.

```powershell
.\.venv\Scripts\python.exe -B -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -m pip check
```

Быстрые тесты проверяют отказы и контракт API без загрузки больших моделей. Перед демонстрацией также обработайте реальный рукописный конспект и сравните распознанный текст, формулы и речь с оригиналом.

Для медленной проверки почерка нужны локальные снимки и ручные расшифровки. Они не включаются в Git из-за содержания пользовательских конспектов. По умолчанию скрипт ищет их в `img_for_test/` и `tests/fixtures/handwriting_ground_truth.json`; можно передать свои пути через `--images-dir` и `--references`:

```powershell
.\.venv\Scripts\python.exe -m scripts.benchmark_handwriting --output reports/ocr_comparison/local_run.json
```

Эти несколько снимков помогают находить регрессии, но не служат оценкой качества на всех почерках. Новые снимки добавляйте только после ручной расшифровки и проверки эталонного текста.

По умолчанию проверяется весь путь OCR (`pipeline`), включая детектор и выбор резервного разделения строк. Отчёт JSON содержит текст, CER/WER, время и пиковый рабочий набор процесса. Латинские буквы и цифры в ошибочном тексте учитываются в метриках. Варианты предобработки выбираются повторяемым `--variant`, например `--variant processed --variant binary`. Для экспериментов доступны `--precision int8|fp32`, `--kv-cache on|off` и `--beams 1|2|3|4`.

В отчёте `detection` отдельно сохраняются найденные интервалы строк. Для точных precision/recall/F1 разметьте их вручную в JSON вида `{"real10.jpg": [[top, bottom], ...]}` и передайте путь через `--line-regions`. Координаты относятся к подготовленному изображению (не более 1920 пикселей по длинной стороне). Одна лишь текстовая расшифровка не позволяет честно измерить точность обнаружения строк.

Сервер обрабатывает фрагменты пакетами до `OCR_BATCH_SIZE=6` на обоих путях OCR. Текущие параметры по умолчанию: `TROCR_QUANTIZE_DECODER=true`, `TROCR_USE_KV_CACHE=true` и `TROCR_NUM_BEAMS=2`. Кэш и число вариантов декодирования влияют на текст: на семи локальных страницах суммарная ошибка снизилась, но на отдельных почерках были регрессии. В журнале запуска указаны фактически выбранные модель, точность, кэш, пакет и число вариантов.
