# Мобильный клиент

Исходный код первой версии Flutter-клиента находится в [app](app/README.md). Здесь также лежит зафиксированная схема [OpenAPI](api/openapi.v1.json). Её источник — запущенный сервер `/openapi.json`; после изменения маршрутов обновляйте снимок командой `python -m scripts.export_openapi`. Инструкция по проверке и запуску находится в `app/README.md`.

## Адрес и обмен

В настройках клиента хранится изменяемый базовый адрес сервера. Для физического телефона в той же Wi-Fi-сети нужен адрес ноутбука вида `http://192.168.x.x:8000/`, а не `localhost`. Сервер запускается командой `python run.py`; `GET /health` возвращает HTTP 200, когда модели и FFmpeg готовы. `GET /info` показывает устройство, движок речи и заполненность очереди. Для демонстрации используется доверенная локальная сеть. Перед использованием через недоверенную сеть нужен HTTPS: [Android предупреждает](https://developer.android.com/privacy-and-security/risks/cleartext-communications), что HTTP позволяет перехватить и изменить передаваемые фотографии и ответы.

1. Перед отправкой снимка создать и локально сохранить UUID. Отправить JPEG, PNG или WEBP запросом `POST /api/v1/recognition/upload`, `multipart/form-data`, поле `file`, заголовок `X-Upload-Id: <UUID>`. Успех: HTTP 202, `{"task_id":"...","status":"pending"}`; `task_id` совпадает с UUID. Максимум 15 МиБ, 20 млн пикселей, 6000 пикселей по стороне. Эти пределы могут быть изменены в `.env`. Заголовок необязателен для старых клиентов, но нужен для безопасного повтора загрузки после обрыва сети.
2. Сохранить `task_id` и локальную копию снимка до успешной обработки. Опросить `GET /api/v1/recognition/status/{task_id}` примерно раз в 1–2 секунды. Статусы: `pending`, `processing`, `completed`, `failed`. При потере ответа на upload проверить статус по заранее сохранённому UUID. Если сервер ответил 404, повторить upload **того же снимка и того же UUID**. Повторный upload вернёт существующую задачу без повторного OCR. После перезапуска сервера готовые результаты сохраняются; прерванная задача становится `failed` и требует новой отправки снимка с новым UUID.
3. После `completed` запросить `GET /api/v1/recognition/result/{task_id}`. После `failed` запросить тот же адрес: манифест содержит понятную ошибку и доступный распознанный текст. При незавершённой задаче адрес возвращает HTTP 202.
4. При `completed` сформировать адрес MP3 из базового адреса и относительного `audio_url`, например `http://192.168.x.x:8000/audio/lecture_....mp3`. Сервер отдаёт `audio/mpeg`. Сохранить MP3 и манифест на телефоне для прослушивания без сети.

HTTP 429 означает заполненную очередь; выдержать паузу из заголовка `Retry-After` и повторить отправку с тем же UUID. HTTP 413 — уменьшить снимок, 415 — пересохранить в поддерживаемом формате, 503 — показать «Сервер пока не готов». HTTP 404 при чтении статуса означает неизвестный `task_id`; HTTP 409 при загрузке — UUID уже использован для другого снимка. Если снимок изменён, создать новый UUID.

## Манифест и плеер

`full_text` — распознанный текст, `spoken_text` — фраза, переданная синтезатору. Массив `chunks` уже упорядочен по `index`. У каждого фрагмента есть `content_type` (`text` или `formula`), исходный `text`, `spoken_text`, `confidence`, прямоугольник `bbox=[left, top, right, bottom]` и времена `start_time`, `end_time`, `duration` **в секундах**. `image_width` и `image_height` — размеры исходной фотографии в пикселях; `bbox` выражен в той же системе координат. Для подсветки на экране масштабировать координаты пропорционально отображённому фото. `confidence` нельзя трактовать как вероятность правильности TrOCR: это оценка исходного детектора.

Переход к следующему/предыдущему фрагменту означает перемотку единого MP3 к его `start_time`. `total_duration` соответствует концу последнего озвученного фрагмента; длительность закодированного MP3 может отличаться на несколько десятков миллисекунд. Для выделения текущего фрагмента выбрать интервал, содержащий текущую позицию; во время паузы между фрагментами сохранять предыдущий фрагмент.

Первая версия клиента: экран подключения, съёмка или выбор фотографии, экран ожидания со статусом, экран результата с доступным плеером и крупными кнопками, настройка светлой/тёмной темы и размера текста. Метки для TalkBack/VoiceOver должны озвучивать назначение каждой кнопки и текущий статус без необходимости смотреть на экран. [Руководство Flutter по доступности](https://docs.flutter.dev/ui/accessibility) рекомендует проверять экран со службами чтения, размером касаний не менее 48×48 и крупным системным шрифтом. Голосовые команды и виброотклик обрабатываются на телефоне; API не принимает аудиокоманды. Для MVP подходят команды «воспроизвести», «пауза», «следующий фрагмент», «предыдущий фрагмент», «повтори формулу». Обработка формул и синтез остаются на сервере.

Клиент хранит список `task_id` локально, так как сервер не предоставляет общий список лекций: без аутентификации он мог бы раскрыть чужие результаты другим устройствам в сети. Позднее для нескольких пользователей понадобится отдельная схема доступа.

## Проверка связи перед началом Flutter

```powershell
python run.py
python -m scripts.smoke_client_api --base-url http://127.0.0.1:8000 --image test_lecture.jpg
```

Вторую команду выполнять в отдельном терминале. Она проверяет весь маршрут, временные метки, координаты и скачивание MP3. На телефоне заменить `127.0.0.1` IP-адресом ноутбука и проверить доступность `/health` в браузере телефона. Клиенту Android нужно разрешение `INTERNET`; его настройка описана в [документации Flutter](https://docs.flutter.dev/cookbook/networking/send-data). Для локального HTTP при разработке потребуется явно разрешить такой трафик настройкой Android Network Security Configuration; публичную версию следует подключать по HTTPS.

Команды проверки и запуска приведены в [инструкции приложения](app/README.md). Debug APK уже собран; следующая проверка UI — запуск на реальном Android-устройстве с TalkBack и крупным системным шрифтом. Для последующей сборки и проверки iOS потребуется среда macOS/Xcode по [руководству Flutter](https://docs.flutter.dev/platform-integration/ios/setup).
